# A real dependency change in the public report

The static site build includes `filesystem-dependencies.html`, generated by the
existing offline metadata renderer from the retained native server snapshots.
The build checks the complete comparison against the retained CLI result:
13 changed schemas, two unchanged entries and no added, removed or unpaired
definitions. It also includes both snapshots, the full comparison and the
original capture observations as direct JSON downloads.

The underlying experiment uses the official filesystem server `2025.8.21` under
Zod 3.25.76 and 4.6.7, with identical compiled entrypoints. These are pinned
historical installations, not an allegation about the latest server version.
Read-only discovery uses an empty allowed directory; no MCP tool is called and
no filesystem contents are read. The [original study](../README.md#real-dependency-resolution-control)
retains registry integrity, dependency locks, independent wire probes and the
upstream license. Rendering the example does not install or contact the server.

```sh
npm ci
npm run build:site
python3 -m http.server 4672 --bind 127.0.0.1 --directory site
# In another shell:
node studies/metadata-diff/publication/browser.mjs http://127.0.0.1:4672/ /tmp/mcplint-real-report
```

The browser program checks the four removed `read_text_file` schema fields,
filters the report, preserves all 13 changes in the downloaded JSON, toggles
the theme with the keyboard, and reopens the actual served HTML offline. It
uses Chromium/Firefox at desktop and phone widths. Public HTTP byte equality
and hosted workflows require separate receipts. This source change does not
publish an npm version.

The [fresh native replay](native.json) on 2026-10-18 reconstructs both retained
locks and reproduces all 13 changes. Every snapshot field except the capture
timestamp matches the retained input. The [local browser receipt](local-browser.json)
records eight complete hosted/standalone views and eight full JSON downloads;
all four screenshots were opened and inspected. Accessibility violations,
page errors and HTTP requests after disconnecting are zero. Firefox's implicit
origin-favicon probe is blocked by the report's existing `default-src 'none'`;
that diagnostic is retained separately rather than changing the content policy.
