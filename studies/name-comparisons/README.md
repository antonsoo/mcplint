# Name comparisons that survive long metadata

The `naming/shadowing` rule compares names from different servers. Before this
change it allocated `(a.length + 1) * (b.length + 1)` JavaScript numbers for every
pair, even though the rule only uses distances of one or two edits. Two names
of 8,198 characters require over 67 million cells.

The retained CLI capture starts two **controlled local MCP SDK servers** that
only return tool definitions. It does not call tools, inspect user configs, or
contact external services. Under a 256 MiB V8 old-space limit, both the similar
and unrelated long-name cases abort with `heap out of memory`, before writing
any JSON report. Names outside the recommended length still need auditing:
MCP's [tool-name guidance](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx)
is a SHOULD, and the collector retains malformed metadata for inspection.

The replacement computes a five-diagonal Levenshtein band in two five-cell
rows. No path using at most two insertions/deletions can leave that band.
Equal prefixes/suffixes contribute no edits; a row whose minimum exceeds two
cannot lead to a qualifying result. Distances through two are exact; all
larger distances return a sentinel. This is the thresholded approach described
by [Ukkonen, Algorithms for approximate string matching (1985)](https://www.cs.helsinki.fi/u/ukkonen/InfCont85.PDF).
Names are lowercased once per tool rather than once per pair.

## Actual CLI results

Node 26.7.0, Linux/WSL2, 14 vCPU, 48 GB RAM. Single observations, including
startup and two stdio handshakes; these are not statistical performance claims.
The before revision is `ff233d8`; inputs are generated by `verify.py` and each
retained result includes both SHA-256 input hashes.

| Input | Before | After |
| --- | --- | --- |
| Two 8,198-character names, one edit apart | Heap exhausted; no report | 0.625 s; complete report, two invalid-name errors, one shadowing warning |
| Two unrelated 8,198-character names | Heap exhausted; no report | 0.662 s; complete report, two invalid-name errors, no shadowing warning |
| An 8,198-character and a 13-character name | 1.003 s; complete | 0.659 s; identical summary |
| 600 valid names from each of two servers | 5.233 s; complete | 1.488 s; identical summary |

The long-name cases correctly exit 1 with `--fail-on error`. "Complete" means
all configured checks ran; it does not mean the supplied metadata is acceptable.
The remaining warnings, estimated token counts and scores are in
[`before.json`](before.json) and [`after.json`](after.json).

## Checking that findings did not change

- The test oracle computes an independent full edit-distance matrix for every
  pair of strings over `a`, `b`, `c` through length five: **132,496 pairs**.
  Additional cases exercise surrogate units, Unicode case folding, 100,000-unit
  names, the 30% length threshold, and case-only differences.
- `corpus.mjs` reads the existing pinned public registry snapshots: **1,304
  servers, 25,799 tool definitions**. It forms artificial groups of eight
  servers to exercise cross-server comparisons; these are not observed client
  installations. Across **164 groups**, all **38 findings** and their complete
  serialized order match the baseline SHA-256 digests. The rule-only replay
  took 6.775 s before and 0.229 s after in these single observations.
  Both manifests, every input hash and every group digest are retained in
  [`corpus-before.json`](corpus-before.json) and [`corpus-after.json`](corpus-after.json).

```sh
npm ci
TMPDIR=/tmp python3 studies/name-comparisons/verify.py --out /tmp/name-results.json
node studies/name-comparisons/corpus.mjs dist /tmp/name-corpus.json studies/name-comparisons/corpus-before.json
```

The last command requires the registry cache described in
[`../registry-census/README.md`](../registry-census/README.md); caches are not
committed. To reproduce the failure, build `ff233d8` separately and give its
`dist/cli.js` to `verify.py --cli ... --observe`. The fixture server's SDK
comes from this checkout's locked install. `--node` selects another runtime.
Each child has a 20-second watchdog; POSIX process groups and disabled core
dumps keep a failing baseline contained.

## Scope

This removes quadratic memory and time **per name pair**. Pair enumeration and
the independent description-similarity rule remain quadratic in tool count.
It is not a global resource budget for arbitrary server metadata. Existing
case-only behavior, Unicode code-unit semantics and the rule's heuristic
accuracy are unchanged. This is an unreleased source change, not an npm release.
